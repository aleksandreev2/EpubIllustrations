# Разработка и выпуск

## Окружение

Node.js 22.4+ и npm. `package-lock.json` фиксирует зависимости. Windows-сборка
создаётся на Windows; пользователю готового приложения Node.js не нужен.

```bash
npm ci
npm test
npm start
```

## Структура

| Файл | Назначение |
| --- | --- |
| `src/main.js` | Окно Electron, диалоги, загрузка ссылок, запись результатов и настройки |
| `src/preload.js` | Ограниченный API между интерфейсом и главным процессом |
| `src/epub.js` | Порядок EPUB spine, HTML-ссылки, вложенные изображения, обложки |
| `src/export.js` | Безопасные имена, определение формата, структура экспорта и ZIP |
| `src/image-options.js` | Проверка параметров, размеры без увеличения, подписи форматов |
| `src/image-converter.js`, `src/converter.js` | Изолированное локальное преобразование встроенными кодеками Electron |
| `src/image-settings-ui.js` | Окно формата, качества и размера |
| `src/library.js` | Атомарное сохранение библиотеки, выбора, структуры экспорта и истории |
| `src/history-ui.js` | История сохранений и действия с завершёнными результатами |
| `src/renderer.js` | Галерея, выбор, предпросмотр, масштаб, поворот, авторство |
| `src/viewer-math.js` | Геометрия размещения и масштабирования |
| `src/updates.js` | Стабильные версии GitHub, кеш, настройки и ограничения частоты |
| `src/update-install.js` | Проверка сборки, потоковая загрузка, SHA-256 и помощник замены portable |
| `src/update-runtime.js` | IPC, уведомления Windows, подтверждение обновления и запуск |
| `src/updates-ui.js` | Полоса уведомления, прогресс и настройки обновлений |
| `tests/` | Проверки без пользовательских книг и без сети |
| `scripts/create-demo.cjs` | Исходные демонстрационные книги и иллюстрации |
| `scripts/capture-screenshots.cjs` | Снимки работающего Electron через локальный Chromium DevTools Protocol |

Интерфейс написан на HTML/CSS/JavaScript. Node.js в renderer отключён;
включены изоляция контекста, sandbox и Content Security Policy. Названия книг
и глав добавляются в DOM как текст. EPUB не исполняется как веб-страница.

Сканер читает изображения из `img`, SVG `image`, ссылок на изображения и
неиспользованных файлов картинок. Для сетевых изображений нужен публичный HTTPS;
есть ограничение 30 МБ, тайм-аут и проверка содержимого ответа. Приложение не
передаёт cookies сайта и не выполняет вход в аккаунт.

## Демоматериалы и скриншоты

```bash
npm run demo
npm run screenshots
npm run images:smoke
npm run images:ui-smoke
```

Первый скрипт создаёт книги в `examples/generated/`, второй — пять снимков
в `docs/images/`. Он запускает временный экземпляр приложения с локальным
портом отладки и отдельными настройками, загружает только эти книги, проверяет
просмотрщик, обновления и авторство, сохраняет все три структуры и перезапускает
приложение для проверки истории, выбора и недоступного исходника. Для публичных
снимков используется вымышленный путь вывода.

`images:smoke` проверяет реальные кодеки, качество, прозрачность, JPEG с белым
фоном, ориентацию EXIF, первый кадр GIF, ZIP и защиту от обрезания длинных WebP.
`images:ui-smoke` проверяет окно настроек, три формата экспорта, размеры,
отмену, историю и перезапуск; он создаёт шестой снимок `format-quality.png`.
Для проверки собранной portable-версии задайте `EPUB_CAPTURE_EXECUTABLE`.

Преобразование использует встроенный [Canvas.toBlob](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob)
в скрытом sandbox-окне без доступа к Node.js, сети и пользовательским книгам.
В режиме «Оригинал» кодеки не вызываются. Веб-движок может обрезать WebP со
стороной больше 16383 пикселей: приложение проверяет итоговые размеры до кодирования.

## Сборка Windows

```bash
npm run dist
npm run checksums
```

В `dist/` появятся:

- `EpubIllustrations-1.2.0-Setup.exe` — установщик NSIS с выбором папки;
- `EpubIllustrations-1.2.0-Portable.exe` — версия без установки;
- `SHA256SUMS.txt` — контрольные суммы файлов.

Номер в именах берётся из `package.json`. Дистрибутив включает Electron,
fflate и сведения об их лицензиях. Персональные книги, скриншоты из реальных
библиотек и локальные настройки в сборку не включаются.

## Публикация

1. Обновить версию и `CHANGELOG.md`, выполнить тесты и собрать оба EXE.
2. Проверить запуск готового приложения, README и скриншоты.
3. Создать и отправить тег вида `v1.1.0`.
4. Опубликовать GitHub Release с установщиком, переносимой версией,
   `SHA256SUMS.txt` и описанием изменений.

Также доступен ручной workflow **Windows release**: он принимает существующий
тег, повторяет тесты и сборку на Windows runner, затем создаёт или обновляет
соответствующий релиз. Обычные push и Pull Request запускают только проверки.

## Проверка обновлений

```bash
npm run updates:smoke
npm run updates:download-smoke
```

Первый сценарий проверяет помощник Windows на инертных файлах с кириллицей,
кавычками и пробелами в пути. Он проверяет замену, отказ при неправильном хеше
и восстановление предыдущего файла после искусственного сбоя запуска,
не запуская EXE. Второй дополнительно скачивает последний публичный Portable
из GitHub и проверяет размер и SHA-256; скачанный файл также не исполняется.

Модуль обновлений принимает только стабильные релизы этого репозитория и точные
имена `EpubIllustrations-<version>-Setup.exe` / `-Portable.exe`. Для запуска
обязателен SHA-256 из метаданных GitHub. При публикации сначала загрузите все
артефакты и только затем открывайте релиз. Данные книг в запросы GitHub не входят.

Для разработки автоматические проверки по умолчанию отключены. Скриншоты
используют отдельную временную папку настроек. Переменная
`EPUB_ILLUSTRATIONS_USER_DATA` позволяет задать такую папку для других локальных
проверок, не затрагивая обычные настройки приложения.
